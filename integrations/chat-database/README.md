# 网页聊天数据库提取

入口：**记忆中心 → 导入聊天记录 → 从微信数据库提取**。

这是一套浏览器本地读取实现，基于对用户提供的 MemoTrace 0.2.8 Windows 程序的静态互操作分析。原程序没有被执行，其代码和依赖没有直接移植到产品中；详细分析见 [分析记录](../../docs/memotrace-database-analysis.md)。

## 使用与范围

1. 选择同一账号、已完成复制的 `.db` / `.sqlite` 数据库。可同时选择消息分片和联系人库。
2. 明文 SQLite 可直接提取。加密库需要用户提供已有的 64 位十六进制密钥；也接受带 16 字节盐值的 96 位原始密钥。
3. 提取后逐条预览，选择要保存的记忆；也可导出标准 JSON 或生成年报。

支持按实际表结构识别 Windows `MSG`、Mac 风格 `Chat_*`、新版 `Msg_*` 消息表，支持可直接解码的 UTF-8 和 Zstd 文本。联系人备注可从兼容的 `Contact` 表读取；无法确定发送者或哈希会话名称时会保留编号或显示“未识别”，不会编造联系人。

加密参数通过第一页 HMAC 校验确认，包括原程序的 Windows 3.x 配置、SQLCipher 3 的 1024/4096 字节页，以及 SQLCipher 4 的 4096 字节页。原始密钥和派生密钥配置分别尝试，匹配后逐页验证。不同微信版本可能使用额外压缩字典、不同字段或不同加密方式，不能据此承诺所有版本都兼容。

**当前不提供 Windows/Mac 进程读内存、自动取密钥、运行中的数据库快照或 WAL 合并，也不提取图片、语音和视频。** 浏览器版本可在两端运行，但它不是原桌面程序自动取密钥流程的完整替代。自动取密钥必须另行实现并验证对应系统的本机组件。

读取有未合并 WAL 的数据库可能缺失新消息，因此选择列表发现 `-wal` / `-shm` 会停止，并提示准备已完成的副本。完整性检查能发现部分损坏，不能证明未提供的 WAL 没有额外消息。

单个文件最多 256 MB，每批最多 512 MB、40 个文件和 20 万条文本。达到限制、跳过非文本、解码失败及单个数据库失败均在结果明细显示。数据只保留在浏览器内存中，用户确认保存的证据除外；密钥不写入本地存储、不返回到结果中，也不发送到服务端。

## 开发

已将必要的 SQLite/WASM 和 Zstd 解码资源放在 `assets/vendor/chat-database/`，无需额外启动后端。主网页和桌面应用均提供 `.wasm` MIME。

```sh
npm ci --prefix integrations/chat-database --ignore-scripts
npm run vendor --prefix integrations/chat-database
npm test --prefix integrations/chat-database
```

测试使用本项目生成的合成数据库；`test/fixtures/windows-encrypted.db` 的公开测试密钥为 `11` 重复 32 次。这些文件不含真实账号、真实联系人或真实聊天。加密测试使用 Node/OpenSSL 产生参考密文，解密实现使用浏览器 WebCrypto，避免以同一个解密实现生成预期结果。真实微信账号与 Windows/Mac 原生环境尚未进行端到端验证。
